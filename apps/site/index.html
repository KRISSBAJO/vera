01 — Trust model

Verified, or asserted. Never both.

This is the distinction the whole system rests on. An agent telling VERA that the tests passed is not evidence that the tests passed — and no amount of confidence in its tone changes that.

Verified

VERA went and looked

A pull request's real approval state. Its real check runs. The migration files actually in the diff. Facts fetched under a time budget, by us, from the source.

  • Can satisfy a prerequisite
  • Carries EVIDENCE.VERIFIED
  • Absence is stated, never assumed safe
Asserted

Something told us

Anything the runtime sends: the agent's own claims, the user it says it is acting for, the environment it says it is in. Useful context. Not proof of anything.

  • Can never satisfy a prerequisite
  • Carries EVIDENCE.ASSERTED
  • Can raise severity, never lower it
02 — The artefact

The product is the token

An approval not bound to a specific action is a permission slip. VERA's token is an Ed25519 signature over a hash of the exact command, target and environment — so changing one flag between asking and executing invalidates it.

Protected header
{"alg":"EdDSA","kid":"k_bce2163f-df6f-41d4-9581-8ed3fa930a85","typ":"vera-decision+jwt"}
Payload — the binding
{
  "decision": "ALLOW",
  "action_hash": "sha256:a7b3160d95beb6de8c22422c095a347ede0096f1213438444ebdec91beb43d19",
  "aud": "adapter:your-laptop",
  "approver": ["ops@logaxp.com"],
  "jti": "jti_9f2c…",  "exp": 1789217431
}

The hash is RFC 8785 canonical JSON over a fixed field set, computed byte-identically by the service and by the adapter. jti is single-use. aud names the one receiver allowed to spend it.

Signature
Ed25519 — verified offline against the tenant's published JWKS. In production the private
half lives in AWS KMS and never reaches the service process.
03 — Sequence

What happens in those forty milliseconds

A real sequence, so it is numbered. Every step can refuse.

01

The adapter asks, before the tool runs

A command hook or an SDK guard hands VERA the tool, arguments, target and environment — and computes the action hash locally, from the same shared code.

02

VERA reads the command itself

Policy-visible arguments the command settles are derived here, not taken on trust. If the runtime described the action differently, that disagreement is a finding in its own right.

03

Evidence is gathered, under a budget

Only what VERA can verify itself. Anything that misses the budget is EVIDENCE.MISSING — which does not satisfy a prerequisite.

04

Policy evaluates, deterministically

Cedar, not a language model. Most-restrictive-wins. A policy error becomes SYSTEM.FAIL_CLOSED, never a silent allow.

05

Baselines add severity, never remove it

Novelty, time-of-day, magnitude and burst signals can escalate a decision. They can never talk one down.

06

A human decides, if it needs one

Separation of duties excludes whoever requested the action. The reviewer sees the agent's text inside a quarantine region, where it cannot impersonate VERA's own words.

07

The token is signed, spent once, audited

The adapter recomputes the hash at execution. A mismatch is TOKEN.HASH_MISMATCH and counts as a bypass. Every signature has a matching audit event.

04 — Integration

Two lines in the runtime you already use

The security-critical path — decide, verify the token, then run — is one shared implementation, not one per adapter.

Claude Code

A local command hook on PreToolUse / PostToolUse

# writes settings and hooks for you
npx vera-hook init \
  --endpoint https://vera.internal \
  --aud adapter:your-laptop \
  --acting-for you@example.com

# ALLOW  → runs, with a verified token
# REVIEW → holds, then allow / deny / ask
# BLOCK  → denied, with the reason shown

Wrap only the tools you care about

05 — Honestly

What VERA is not

A pilot that starts with an accurate picture is the only kind worth running. This section is in the product documentation too, word for word.

Not a sandbox

It decides; it does not contain. An agent that ignores the adapter is not stopped by VERA.

Not a runtime guarantee

A hook can be disabled. VERA raises the cost of an unreviewed action and makes it visible. It does not make it impossible.

Not an LLM judge

No model decides anything consequential. Models draft policies and summarise for reviewers; they are never the authority.

Not a compliance certificate

It produces evidence a person can use. It does not make you compliant with anything.

Not finished

The threat model lists eight accepted risks. They are accepted, not solved — and they are written down for you to read before you decide.

Thirty days, one repository, your infrastructure

Nothing leaves your network. We want the decisions VERA got wrong — the review that was obviously fine, the thing it let through that you would have wanted to see. A pilot where VERA blocked nothing and annoyed nobody is a failure, not a success.
